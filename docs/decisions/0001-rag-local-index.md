# Decision 0001 · local RAG index and provisional retrieval settings

**Date:** 2026-10-20 · **Status:** retrieval settings provisional; bounded provider retry verified live

We keep the 13 reviewed Markdown snapshots in Git and store generated embeddings in ignored `logs/rag_index.json`. This lets the RAG slice run without changing Nino's PostgreSQL schema, migrations or verification scripts. The index records model ID, dimensions and corpus hashes, so a changed document forces a rebuild. It is local to each developer's machine and must not be mistaken for shared database state.

The first ranking setting is hybrid cosine/BM25, `k=5`, threshold `0.45`. This is an implementation starting point, not a measured optimal threshold. Offline tests cover ranking, low-score refusal before generation, citation validation, and index drift.

The user built a live 26-chunk index and ran the first golden set: `evals/results/2026-10-20-144012-live-k5.json` records **3/10, below 0.70**. Query embeddings succeeded, and required documents appeared among retrieved chunks, but nine generation attempts were refused under the old combined `invalid_or_unavailable_model_reply` reason. One generation completed successfully. Safe diagnostics then identified transient Gemini HTTP 503 responses. A second unchanged live run, `evals/results/2026-10-20-144811-live-k5.json`, records **7/10, meeting 0.70**; its three failures are all HTTP 503.

Changing `k` or the retrieval threshold cannot fix a provider HTTP 503. The answer service retries only HTTP 429/500/502/503/504 and transport timeouts, with at most three generation attempts and short backoff. Permanent HTTP errors and invalid model replies are never retried. Each question writes one answer/refusal line, with `generation_attempts`; each provider attempt writes its own usage line. The third live run, `evals/results/2026-10-20-145601-live-k5.json`, records **9/10** under the original scorer. Retries recovered several transient errors; g10 still failed with HTTP 503. The post-run audit found that g5's passing refusal came from model timeout rather than source reasoning, so the source-based result is **8/10**, still above 0.70. The scorer now accepts refusals only for `low_retrieval_score` or `source_does_not_answer`; the unchanged golden questions remain. The full offline suite passed **186 tests** after this correction. Retrieval settings remain provisional; changing them is not justified by these provider failures.

The documents contain real performer names because the requester chose to retain the real corpus. Lab 4's shareable-corpus guidance asks for no real names; the team should review this before treating the corpus as a compliant submission. The runtime must still refuse unknown facts and current availability.
